# Famo

輕量的本機個人任務管理 App，支援直接輸入、編輯、勾選完成與拖曳排序。介面以列表與操作為主，縮小頁邊距、採較大字級，不顯示標語、裝飾性說明或頁尾。

待實作功能見 [功能待辦](TODO.md)。

## 任務操作

- 快速新增支援 `- [ ] 任務`，按 Enter 後立即接著輸入下一件事，中文選字不誤送出。任務使用設定頁的預設類型、該類型的預設階段與預設優先順序。
- 點列表文字直接修改任務標題：Enter 或離開欄位儲存，Escape 取消。清空後再按一次 Backspace 才刪除任務；刪除採軟刪除。
- 點任務列的狀態 chip 可直接展開該類型的階段選單，選取後立即儲存，保留選項的自訂顏色。
- 方形 checkbox 直接完成／恢復整件任務。舊步驟資料保留，但介面不再顯示或操作步驟，也不再顯示步驟進度。
- 六點把手支援滑鼠、觸控及鍵盤排序；搜尋後排序只交換可見任務的位置。順序存入 SQLite。
- 工具列最右側的「新增任務」直接開啟完整表單，包含標題、描述、任務類型、優先順序與多筆連結。連結使用設定中的種類與預設值，可重複選擇相同種類，建立前可移除不需要的列。描述可自由填寫目標、背景與完成條件。
- 詳細頁點標題或描述直接編輯，離開欄位儲存、Escape 取消。標題以 Enter 儲存；描述的 Enter 換行，Ctrl／⌘＋Enter 儲存，也可使用欄位下方的儲存／取消。已完成任務也可修改標題和描述。
- 類型、流程階段與優先順序可在詳細頁直接選取；切換類型時使用新類型的預設階段。新增 HTTP／HTTPS 連結時以 select 選擇種類，同一種類可以新增多筆，例如同一任務的兩個 PR。進展歷程預設收合，點擊後展開。
- 所有內容寫入都帶版本。版本衝突與儲存失敗會保留編輯草稿，避免覆蓋其他視窗或 Agent 的更新。

首頁只保留一個主要任務列表，所有未完成任務依手動排序呈現，不因等待原因或提醒到期而重新分區或移動位置。流程階段保留在任務列的 chip 及詳細頁中；等待與提醒功能已從介面移除，既有欄位保留作舊資料相容。已完成任務放入完成紀錄。任務每 30 秒及視窗重新聚焦時同步。

## 日期任務

導覽列的「今日」開啟今天的任務清單；`<`、`>` 可切換前後一天，目前日期獨立顯示為頁面標題，右側緊接靠左排列的 `< [ 今日 | ⌄ ] >` 日期控制列。「今日」與下拉箭頭組成同一個分段按鈕：點「今日」回到瀏覽器當地日期，點箭頭展開月曆選日，也可在選單中輸入日期。月曆支援切換月份、方向鍵選日、Escape 關閉及點選外部收起。原本的任務列表與完成紀錄仍保留，可跨日期查看任務。

每件任務可指定一個所屬日期，也可留空。日期頁只顯示屬於該日期的任務，未完成在上、已完成在下，並顯示完成數。勾選完成或恢復任務都不會改變所屬日期；今天補勾昨天的任務，仍留在昨天，不會出現在今天。

在日期頁快速新增或開啟完整表單時，預設使用正在查看的日期；在一般任務列表新增則預設無日期。詳細頁點「任務日期」可修改，進入編輯後可清除日期；已完成任務也可調整。儲存失敗或版本衝突會保留日期草稿。快速新增的草稿即使切換頁面後重試，仍使用原本指定的日期。

日期頁下方有預設收合的「先前未完成」，列出所屬日期早於目前查看日期的未完成任務，並顯示原日期；無日期任務不納入。可逐筆或多選「移到這天」，也可直接勾選完成。任務不會自動跨日移動。多選移入逐筆檢查版本並儲存，失敗項目保留在原日期與選取狀態，錯誤提示後可確認最新內容再重試。

## 連結種類設定

導覽列的「連結種類」可新增、改名、排序、停用、刪除連結種類與指定預設值。內建 GitHub PR、GitHub Issue、Asana、Slack、文件與其他，連結種類選單與連結維持原本無配色樣式，不顯示配色操作。種類使用固定 ID；同一任務允許多個相同種類的連結，每一筆 URL 分別保留。

改名時同步更新既有連結的顯示名稱；停用不影響既有連結，但新增時不可選用。刪除會將既有連結改用新的預設種類，保留所有 URL 與連結筆數。這些設定與任務連結會在同一交易更新，任務版本與歷程也會同步記錄。

## 下拉選項設定

導覽列的「選項」可以編輯任務類型、各類型的流程階段與優先順序。支援新增、刪除、改名、排序、預選／自訂顏色、停用與預設值；選項色彩同步顯示在任務列表、詳細頁與選單。首頁維持單一列表，不依流程階段或等待／提醒時間分區。

每個選項有固定 ID，修改名稱與顏色不會改寫任務關聯。停用選項會保留既有任務的顯示，新任務不可選用；刪除則會將使用中的任務改到對應的預設類型、階段或優先順序。刪除預設選項時，介面自動選擇第一個仍啟用的選項作為預設，最後一個啟用中的預設選項不可刪除。

刪除在按下儲存後生效。設定與任務改派在同一筆交易提交；受影響任務的版本會遞增，並新增歷程，描述、完成／刪除狀態與排序保持原樣。已開啟的編輯草稿會依版本檢查避免覆蓋改派結果。

## 執行

需要 Go 1.26.5 以上、Node.js 24 LTS 以上與 npm。

```sh
make build
./bin/famo
```

開啟 <http://127.0.0.1:8787>。資料預設存入啟動目錄的 `data/famo.db`。可指定路徑及位址：

```sh
./bin/famo -db /absolute/path/famo.db -addr 127.0.0.1:8787
```

正式執行檔已內嵌前端，搬動時不必搬動 Node.js 或 `web/dist`。修改程式後需重新執行 `make build` 並重新啟動程式。

### 資料升級

資料庫升級至 v4 時會在交易中建立選項設定，將原有 `goal`、`context`、`acceptance` 的非空內容依序加上小標合併成 `description`。原欄位、步驟、連結、歷程、任務版本與排序均保留；之後清空描述不會再次從舊欄位填回。

備份時先停止程式再複製 SQLite 檔案；執行中的 WAL 可能尚未合併到主檔。升級至 v5 會加入連結種類設定，將舊連結種類匯入並綁定固定 ID；保留原種類名稱、URL、重複種類連結、任務版本、歷程與順序。升級後請使用支援 v5 的執行檔。

## 開發與檢查

本專案 Git 操作文字一律使用英文，包括 commit messages、PR titles、PR descriptions 及相關 Git／PR 溝通文字。

先安裝前端依賴，再分別啟動後端與前端：

```sh
cd web
npm ci
```

```sh
make dev-api
```

```sh
make dev-web
```

前端位址為 <http://127.0.0.1:5173>，`/api` 代理到 Go。

```sh
make test                       # Go race tests、TypeScript、前端正式建置
cd web
npx playwright install chromium # 首次安裝測試瀏覽器

npm run format:check
```

瀏覽器驗收會啟動獨立的 `127.0.0.1:8788` 伺服器，使用暫存目錄中的 SQLite，不接觸個人資料庫。測試涵蓋資料升級、設定持久化／驗證／版本衝突、任務原子寫入、拖曳排序、直接編輯、封存步驟不介入列表操作、歷程收合，以及手機操作。

## Agent API

所有路徑同時支援 `/api` 前綴。僅供本機單一使用者使用；預設綁定 loopback，驗證 Host 與瀏覽器 Origin。寫入只接受 `application/json`，單次請求最多 1 MiB。

| 方法與路徑 | 用途 |
| --- | --- |
| `GET /health` | 健康檢查 |
| `GET /settings` | 選項設定及版本 |
| `POST /settings` | 提交完整設定，需帶讀取時的 `version` |
| `GET /workflows` | 類型及階段選項（含固定 ID、名稱、色彩、停用狀態及預設階段） |
| `GET /tasks` | 全部未刪除任務，含已完成任務 |
| `POST /tasks` | 建立任務 |
| `POST /tasks/reorder` | `{"task_ids":["id2","id1"]}` 調整未完成任務的相對順序 |
| `GET /tasks/{id}` | 完整任務 |
| `GET /tasks/{id}/context` | Agent 脈絡，與完整任務相同 |
| `POST /tasks/{id}/actions` | 具版本檢查的任務操作 |

建立任務，只需標題；未提供類型、階段與優先順序時使用設定預設值：

```sh
curl http://127.0.0.1:8787/tasks \
  -H 'Content-Type: application/json' \
  -d '{
    "title": "修復登入逾時",
    "description": "閒置後登入失敗，修復後需通過回歸測試。",
    "scheduled_date": "2026-11-04",
    "links": [{"type_id": "slack", "url": "https://example.com/thread"}],
    "source": "agent:codex"
  }'
```

讀取 context 的 `version` 與 settings 中的選項 ID 後，可原子更新描述、階段與連結：

```sh
curl http://127.0.0.1:8787/tasks/TASK_ID/actions \
  -H 'Content-Type: application/json' \
  -d '{
    "op": "update",
    "version": 1,
    "description": "修復已提交，等待 CI 結果。",
    "links": [{"type_id": "pr", "url": "https://github.com/example/app/pull/1"}],
    "source": "agent:codex"
  }'
```

請替換範例 ID、版本與時間。`type`、`stage` 使用設定中的字串 ID；`priority` 維持非負整數 ID，選項可擴充，沒有 0–2 上限。切換類型時應一併指定該類型的合法階段。新增連結使用 `{"type_id":"pr","url":"https://…"}`，`type_id` 取自 `settings.link_types`；回傳連結另含顯示名稱 `type`。舊版 `type` 名稱輸入仍可對應已設定的種類；未知或已停用種類回傳 `400`。

| `op` | 行為 |
| --- | --- |
| `update` | 更新 `title`、`description`、`scheduled_date`、`type`、`stage`、`priority`、`waiting_reason`、`review_at`、`metadata`；可附加 `links` |
| `rename` | 非空白 `title`，重新命名任務 |
| `set_waiting` | 舊版相容操作：非空白 `waiting_reason`，設定等待；介面已移除 |
| `resume` | 舊版相容操作：清除等待與查看時間；介面已移除 |
| `add_link` | 非空白 `links` 陣列，附加相關連結；同一 `type_id` 允許多筆 |
| `complete_task` | 完成任務，清除等待／提醒，保留描述與歷程 |
| `reopen_task` | 恢復任務為未完成 |
| `delete_item` | 軟刪除任務 |

`scheduled_date` 為可選的日期字串，格式為有效的 `YYYY-MM-DD`（年份 0001–9999），不含時間或時區；建立時省略或設為空字串代表無日期。`update` 省略此欄位維持原值，空字串清除日期，無效日期回傳 `400`。日期保存在既有 SQLite 任務 JSON 文件，無須 schema 升級；舊任務視為無日期。請使用支援日期欄位的執行檔，舊版寫入任務可能遺失此欄位。

省略欄位維持原值，空字串 `description`／`waiting_reason`／`review_at` 清除內容。回傳完整任務，版本遞增一次，並記錄來源與時間。`source` 省略為 `ui`。版本衝突回傳 `409`，應重新讀取並確認適用的修改；請勿直接以新版本覆蓋舊草稿。

舊 `goal`、`context`、`acceptance` 與步驟欄位及操作仍保留 API 相容性；新整合應只使用 `description` 與任務操作。建立時只提供舊內容欄位會合併到描述；之後舊內容欄位與描述各自獨立，不雙向同步。

設定提交使用 `GET /settings` 的完整結構，包含 `version`、`workflows`、`priorities`、`default_type`、`default_priority`、`link_types`、`default_link_type`。類型另有 `stages`、`default_stage`；每個選項包含 `id`、`name`、`color`（`#RRGGBB`）及 `disabled`。移除陣列中的選項即代表刪除，引用該選項的任務會原子改派至預設值；若保留引用請設 `disabled: true`。刪除預設選項時必須同時提交合法的新預設值。陣列順序就是選單順序。`color_presets` 為伺服器提供的唯讀預選色表，提交時不會覆寫內建色表。

排序不修改任務版本或歷程，只交換指定 ID 占用的位置。重複、不存在或已完成 ID 回傳 `400`，不留下部分更新。

錯誤回傳 `{"error":"說明"}`：`400` 輸入錯誤、`404` 找不到任務、`409` 版本衝突、`415` Content-Type 錯誤、`500` 儲存失敗。

## 專案結構

```text
cmd/famo/              啟動、參數、結束處理
internal/tasks/        資料模型、自訂選項、領域操作、SQLite 持久化與遷移
internal/server/       chi HTTP API、本機來源驗證、靜態檔案
web/src/               React 工作台、詳細頁、新增任務與設定頁
web/src/components/ui/ 專案持有的 UI 基礎元件
web/e2e/               Playwright 瀏覽器驗收
web/embed.go           內嵌前端建置產物
```
